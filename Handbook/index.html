01 · Arsitektur Aplikasi

Secara sederhana, aplikasi Cafe_Najwa berjalan seperti ini:

Browser→PHP page→config/database.php→PDO→PostgreSQL→HTML response

Kenapa struktur dipisah?

  • config/ menangani koneksi database.
  • layout/ menyimpan komponen tampilan bersama seperti header, navbar, footer.
  • master/ menangani data kategori, menu, pelanggan, meja.
  • transaksi/ menangani pesanan dan pembayaran.
  • laporan/ mengambil data untuk laporan.
  • auth/ menangani login, register, logout.
  • includes/ berisi middleware/helper seperti auth dan CSRF.
Kalau ditanya: “Kenapa tidak semua kode ditaruh di index.php?”

Karena pemisahan file membuat tanggung jawab kode lebih jelas, mengurangi duplikasi, dan memudahkan pemeliharaan. Header, footer, koneksi database, autentikasi, dan fitur transaksi dapat dipakai kembali dari banyak halaman.

02 · PHP Fundamental yang Wajib Bisa Dijelaskan

Request method

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    header("Location: index.php");
    exit;
}

Artinya: proses hanya menerima request POST. Jika URL dipanggil dengan GET, pengguna diarahkan kembali.

GET vs POST

  • GET dipakai pada source untuk search/pagination karena parameter berada di URL, contoh ?keyword=kopi&page=2.
  • POST dipakai untuk perubahan data seperti tambah, edit, hapus, pembayaran. Ini juga memungkinkan pemeriksaan CSRF pada form perubahan data.

trim(), isset(), ??

$keyword = trim($_GET['keyword'] ?? '');
$id = !empty($_POST['id']) ? (int) $_POST['id'] : 0;
  • ?? memberi nilai default jika key tidak ada.
  • trim() menghapus spasi di awal/akhir input.
  • empty() memeriksa apakah nilai kosong.
  • (int) mengubah input menjadi integer sebelum digunakan sebagai ID.

require / require_once

require __DIR__ . "/../../config/database.php";
require_once __DIR__ . "/../../includes/auth.php";

require memasukkan file lain ke file yang sedang berjalan. require_once memastikan file tidak dimuat berulang kali.

Redirect + exit

header("Location: index.php?pesan=gagal");
exit;

header() mengirim response redirect. exit menghentikan script agar kode setelah redirect tidak ikut berjalan.

PDO

$pdo = new PDO(
    "pgsql:host={$host};port={$port};dbname={$dbname};sslmode=require",
    $username,
    $password
);

PDO adalah interface PHP untuk bekerja dengan database. Pada project ini drivernya adalah PostgreSQL. Setelah koneksi dibuat, query dijalankan melalui $pdo.

Prepared statement

$stmt = $pdo->prepare("
    SELECT id, nama, username, password, role
    FROM users
    WHERE username = :username
    LIMIT 1
");

$stmt->execute([
    ':username' => $username
]);

Query dipisahkan dari data input. Ini penting untuk keamanan dan juga membuat query lebih terstruktur.

fetch(), fetchAll(), fetchColumn()

  • fetch() mengambil satu baris hasil.
  • fetchAll() mengambil banyak baris.
  • fetchColumn() mengambil satu nilai/kolom dari hasil, digunakan pada COUNT.
Pertanyaan jebakan: “Kenapa input ID masih di-cast ke int kalau query sudah prepared statement?”

Prepared statement melindungi struktur SQL dari injeksi, sedangkan casting ke integer membuat tipe data yang diharapkan jelas dan membantu validasi input. Keduanya memiliki fungsi berbeda.

Primary key

Primary key mengidentifikasi satu baris secara unik.

Foreign key

FOREIGN KEY (kategori_id)
REFERENCES kategori(id)
ON UPDATE CASCADE
ON DELETE RESTRICT

CASCADE pada update meneruskan perubahan key yang direferensikan. RESTRICT mencegah kategori dihapus jika masih direferensikan oleh menu.

Constraint

CHECK (harga >= 0)
CHECK (stok >= 0)

Constraint adalah validasi di level database. Jadi aturan penting tidak hanya bergantung pada form PHP.

Relasi pesanan

Karena desain project menetapkan satu pesanan memiliki maksimal satu record pembayaran.

CREATE INDEX IF NOT EXISTS idx_pesanan_pelanggan
ON pesanan (pelanggan_id);

Index membantu pencarian/join berdasarkan kolom tersebut agar database tidak selalu harus memeriksa seluruh tabel.

Q: Apa beda primary key dan foreign key?

Primary key mengidentifikasi record di tabelnya sendiri. Foreign key menyimpan referensi ke primary key tabel lain untuk membentuk hubungan antar tabel.

04 · CRUD

CRUD = Create, Read, Update, Delete.

C

Create

Form mengirim POST → proses.php → INSERT.

R

Read

index.php menjalankan SELECT → fetch/fetchAll → HTML.

U

Update

Form menerima ID → proses.php → UPDATE.

D

Delete

POST → hapus.php → DELETE, dengan validasi/CSRF pada JS11+.

Pola Create

$stmt = $pdo->prepare("
    INSERT INTO users (nama, username, password, role)
    VALUES (:nama, :username, :password, 'petugas')
");

$stmt->execute([
    ':nama' => $nama,
    ':username' => $username,
    ':password' => password_hash($password, PASSWORD_DEFAULT)
]);

Pola Read

$stmt = $pdo->prepare("SELECT ... FROM menu ...");
$stmt->execute($params);
$menu = $stmt->fetchAll(PDO::FETCH_ASSOC);

Pola Update

Data lama dicari berdasarkan ID, form diisi, lalu proses mengirim UPDATE berdasarkan ID tersebut.

Pola Delete

Project JS9 memakai POST untuk delete. Pada JS11/12 delete juga diverifikasi dengan CSRF dan menggunakan prepared statement.

Q: Mengapa delete tidak menggunakan GET?

Karena delete mengubah data dan bersifat destruktif. POST lebih sesuai untuk operasi perubahan dan dapat dipasangkan dengan token CSRF.

05 · Search & Pagination

Search server-side

$keyword = trim($_GET['keyword'] ?? '');

if ($keyword !== '') {
    $whereSql = "WHERE (
        menu.kode_menu ILIKE :keyword
        OR menu.nama_menu ILIKE :keyword
        OR kategori.nama_kategori ILIKE :keyword
        OR menu.status ILIKE :keyword
    )";

    $params[':keyword'] = '%' . $keyword . '%';
}

Pencarian dilakukan di database, bukan mengambil semua data lalu memfilter dengan JavaScript.

Kenapa ILIKE?

PostgreSQL menyediakan ILIKE untuk pencarian pattern yang tidak membedakan huruf besar-kecil. Tanda % berarti karakter apa pun boleh berada sebelum atau sesudah keyword.

Pagination

$page = max(1, (int) ($_GET['page'] ?? 1));
$perPage = 5;
$offset = ($page - 1) * $perPage;

Jika page 1 → offset 0. Page 2 → offset 5. Page 3 → offset 10.

$totalData = (int) $countStmt->fetchColumn();
$totalPages = max(1, (int) ceil($totalData / $perPage));

$query->bindValue(':limit', $perPage, PDO::PARAM_INT);
$query->bindValue(':offset', $offset, PDO::PARAM_INT);

Kenapa COUNT dilakukan terpisah?

Karena aplikasi perlu mengetahui jumlah total record untuk menghitung jumlah halaman, sementara query utama hanya mengambil record untuk halaman aktif.

Q: Apa risiko kalau LIMIT/OFFSET tidak dibind sebagai integer?

Parameter pagination adalah bagian dari kontrol query. Di source, keduanya di-bind dengan PDO::PARAM_INT agar tipe yang dikirim jelas.

06 · Authentication & Session

Register

  1. Ambil nama, username, password, konfirmasi.
  2. Validasi field kosong.
  3. Password minimal 6 karakter.
  4. Konfirmasi harus sama.
  5. Cek username sudah digunakan atau belum.
  6. Password di-hash dengan password_hash().
  7. Insert user dengan role default petugas.
$stmt->execute([
    ':nama' => $nama,
    ':username' => $username,
    ':password' => password_hash($password, PASSWORD_DEFAULT)
]);

Login

$stmt = $pdo->prepare("
    SELECT id, nama, username, password, role
    FROM users
    WHERE username = :username
    LIMIT 1
");

$stmt->execute([':username' => $username]);
$user = $stmt->fetch();

if (!$user || !password_verify($password, $user['password'])) {
    header("Location: login.php?pesan=gagal");
    exit;
}

Session fixation protection

session_regenerate_id(true);

Dipanggil setelah kredensial berhasil diverifikasi, sebelum identitas user disimpan ke session.

Isi session

$_SESSION['user_id'] = $user['id'];
$_SESSION['user_name'] = $user['nama'];
$_SESSION['username'] = $user['username'];
$_SESSION['role'] = $user['role'];

Proteksi halaman

if (!isset($_SESSION['user_id'])) {
    header("Location: /Jobsheet12/auth/login.php");
    exit;
}

Ini adalah bentuk middleware sederhana: halaman berhenti dan redirect jika user belum login.

Q: Kenapa password tidak dibandingkan dengan ==?

Karena database menyimpan hash password. password_verify() membandingkan password plaintext yang dimasukkan dengan hash yang tersimpan tanpa membutuhkan aplikasi mengetahui password asli.

07 · Security

1. SQL Injection

Risiko muncul jika input user digabung langsung ke SQL. Source menggunakan prepared statement:

$stmt = $pdo->prepare("SELECT ... WHERE username = :username");
$stmt->execute([':username' => $username]);

2. XSS

htmlspecialchars($data['nama_menu'], ENT_QUOTES, 'UTF-8')

Output user-controlled diubah menjadi bentuk aman untuk HTML. Pada JS11 tersedia helper:

function e($value): string
{
    return htmlspecialchars((string) $value, ENT_QUOTES, 'UTF-8');
}

3. CSRF

$_SESSION['csrf_token'] = bin2hex(random_bytes(32));

Token acak disimpan di session, dimasukkan ke form, lalu dibandingkan ketika POST.

if (!hash_equals($sessionToken, $postedToken)) {
    http_response_code(403);
    exit('CSRF token tidak valid.');
}

4. Session Fixation

session_regenerate_id(true);

Session ID diganti setelah login berhasil.

5. Password hashing

password_hash($password, PASSWORD_DEFAULT)

Jangan menyimpan password plaintext.

6. Validasi dua lapis

Validasi terjadi di PHP dan beberapa aturan juga berada di database melalui CHECK, UNIQUE, NOT NULL, dan foreign key. Client-side validation saja tidak cukup karena request dapat dibuat tanpa melalui form browser.

Q: Apakah prepared statement sama dengan validasi?

Tidak. Prepared statement melindungi struktur SQL dari injeksi. Validasi memeriksa apakah data sesuai aturan aplikasi. Keduanya saling melengkapi.

08 · Integrasi Transaksi JS12

Alur final

Pilih meja→Buat pesanan→ Stok berkurang→Bayar→ Pesanan tetap Proses→Selesai→ Kosongkan meja

Database transaction

$pdo->beginTransaction();

try {
    // beberapa perubahan database
    $pdo->commit();
} catch (Throwable $e) {
    if ($pdo->inTransaction()) {
        $pdo->rollBack();
    }
}

Tujuannya menjaga konsistensi. Jika salah satu langkah gagal, perubahan yang sudah terjadi dalam transaction dapat dibatalkan.

Row locking

SELECT id, status
FROM meja
WHERE id = :id
FOR UPDATE

Baris meja dikunci selama transaction sehingga proses lain tidak bebas mengubah baris yang sama pada saat bersamaan.

Stok

Saat pesanan aktif dibuat/diproses, stok menu dikurangi. Saat pesanan aktif diedit atau dihapus, stok lama dikembalikan terlebih dahulu sebelum data baru diproses.

Meja

  • Pesanan aktif → meja Terisi.
  • Meja yang tidak Kosong tidak boleh dipakai untuk pesanan baru.
  • Pesanan Dibatalkan → meja dilepas.
  • Pesanan Selesai belum otomatis membuat meja kosong.
  • kosongkan_meja.php hanya mengosongkan meja setelah status pesanan Selesai.

Pembayaran

  • Metode: Cash, QRIS, Debit, E-Wallet.
  • Lunas harus sama dengan total pesanan.
  • Belum Lunas tidak boleh melebihi total pesanan.
  • Satu pesanan hanya memiliki satu pembayaran menurut constraint UNIQUE.
  • Menghapus pembayaran mengembalikan status pesanan menjadi Proses, kecuali dibatalkan.
Q: Kenapa bayar Lunas tidak otomatis membuat pesanan Selesai?

Karena pembayaran adalah status finansial, sedangkan status pesanan menunjukkan proses pelayanan. Pada desain project, makanan masih dapat diproses/disajikan walaupun sudah dibayar.

12 · Troubleshooting

“Koneksi database gagal”

  1. Cek DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD.
  2. Cek database benar-benar ada.
  3. Cek SSL/port PostgreSQL.
  4. Cek apakah environment production sudah memiliki variable.

“Undefined array key”

Biasanya kode membaca $_POST['x'] ketika field tidak dikirim. Gunakan pola default seperti $_POST['x'] ?? '' dan pastikan nama input sama dengan yang dibaca PHP.

Data tidak muncul

Periksa query SELECT, JOIN, WHERE, parameter, dan isi database. Jalankan query yang sama di DBeaver/psql untuk membedakan masalah database dengan masalah tampilan.

Pagination salah

Periksa page, perPage, offset, totalPages, dan apakah keyword ikut dibawa pada link page.

CSRF token invalid

Pastikan form memakai csrf_field(), session aktif, dan endpoint POST memanggil csrf_verify().

Stok berubah setengah

Periksa apakah proses menggunakan beginTransaction(), commit(), dan rollBack() pada exception.

Meja tidak bisa dipilih

Cek status meja. Pada JS12 meja yang statusnya bukan Kosong dianggap sedang digunakan.

13 · Bank Pertanyaan UTS

1. Apa fungsi PDO?

PDO menjadi interface PHP untuk koneksi dan eksekusi query database. Di project digunakan dengan driver PostgreSQL dan prepared statement.

2. Apa fungsi prepare()?

Mempersiapkan SQL dengan placeholder sehingga data dapat diberikan melalui execute(). Ini membantu memisahkan struktur SQL dari input.

3. Apa fungsi execute()?

Menjalankan prepared statement dengan parameter yang diberikan.

4. Apa fungsi fetch()?

Mengambil satu baris hasil query.

5. Apa fungsi fetchAll()?

Mengambil seluruh baris hasil query.

6. Kenapa menggunakan ILIKE?

Karena PostgreSQL menyediakan pencarian pattern yang case-insensitive.

7. Apa rumus offset pagination?

offset = (page - 1) × perPage.

8. Kenapa COUNT terpisah dari SELECT data?

Untuk mengetahui total record dan menghitung jumlah halaman.

9. Apa fungsi password_hash?

Menyimpan representasi hash password, bukan plaintext.

10. Apa fungsi password_verify?

Memverifikasi password yang dimasukkan terhadap hash yang tersimpan.

11. Kenapa session_regenerate_id?

Untuk mengganti session ID setelah login dan mengurangi risiko session fixation.

12. Apa itu CSRF?

Serangan yang memanfaatkan session korban agar browser korban mengirim request perubahan ke aplikasi tanpa persetujuan yang semestinya. Token CSRF memastikan request berasal dari form yang memiliki token session yang benar.

13. Apa itu XSS?

Injeksi script/content berbahaya ke halaman yang kemudian dirender ke pengguna lain. Project menggunakan htmlspecialchars untuk escaping output HTML.

14. Apa itu SQL Injection?

Memanipulasi input agar menjadi bagian dari sintaks SQL. Prepared statement digunakan untuk memisahkan query dari data.

15. Kenapa delete memakai POST?

Karena delete adalah perubahan/destruktif dan membutuhkan perlindungan CSRF.

16. Apa itu transaction database?

Kumpulan perubahan database yang diperlakukan sebagai satu unit sehingga dapat commit bersama atau rollback jika terjadi kegagalan.

17. Apa fungsi rollback?

Membatalkan perubahan yang belum di-commit dalam transaction.

18. Kenapa SELECT ... FOR UPDATE digunakan?

Untuk mengunci baris yang relevan selama transaction, misalnya baris meja/menu, agar pemeriksaan dan perubahan konsisten.

19. Kenapa stok dikembalikan saat pesanan aktif dihapus?

Karena stok sebelumnya sudah dikurangi ketika item pesanan mengambil stok. Menghapus pesanan harus mengembalikan keadaan stok.

20. Kenapa pembayaran Lunas tidak otomatis Selesai?

Status pembayaran dan status pelayanan memiliki makna berbeda dalam desain Cafe_Najwa.

21. Kenapa meja belum kosong setelah pesanan Selesai?

Karena Selesai berarti pesanan selesai dilayani, sedangkan pelanggan masih dapat duduk. Meja baru dikosongkan melalui aksi khusus setelah pelanggan selesai makan.

22. Apa fungsi foreign key?

Menjaga hubungan antar tabel dan referensi data tetap valid.

23. Apa beda UNIQUE dan PRIMARY KEY?

Primary key adalah identitas utama record dan secara konsep menjadi key utama tabel. UNIQUE memastikan nilai pada kolom tidak duplikat.

24. Kenapa database punya CHECK?

Untuk memastikan aturan data juga ditegakkan di level database.

25. Kenapa validasi PHP masih diperlukan jika database punya CHECK?

Agar pengguna mendapat alur error yang jelas sebelum query gagal dan untuk memeriksa aturan yang bersifat aplikasi.

26. Apa fungsi require_once auth.php?

Memastikan halaman hanya bisa dibuka user yang sudah login.

27. Apa fungsi htmlspecialchars?

Escape karakter khusus HTML agar input tidak dirender sebagai markup/script.

28. Apa beda GET dan POST di project?

GET terutama untuk search/pagination; POST untuk operasi yang mengubah data.

29. Apa yang terjadi jika commit tidak dipanggil?

Perubahan transaction tidak difinalisasi sebagai transaksi yang berhasil. Pada alur exception, rollback dipakai untuk membatalkan perubahan.

30. Kenapa credential database tidak boleh hard-code?

Karena source code dapat dibaca/ter-push ke repository. Environment variable memisahkan secret dari kode aplikasi.

14 · Simulasi Tanya Jawab Dosen

Simulasi A — Tunjuk baris kode

Dosen: “Ini prepare() untuk apa?”

Kamu: “Untuk mempersiapkan query dengan placeholder parameter. Data kemudian dikirim melalui execute(), sehingga input tidak langsung digabungkan ke string SQL dan membantu mencegah SQL Injection.”

Dosen: “Kenapa masih pakai validasi?”

Kamu: “Karena prepared statement dan validasi punya tujuan berbeda. Prepared statement melindungi struktur SQL, sedangkan validasi memastikan data sesuai aturan aplikasi.”

Simulasi B — Stok

Dosen: “Kalau pesanan dihapus, stok bagaimana?”

Kamu: “Jika pesanan sebelumnya aktif dan sudah mengambil stok, jumlah detail pesanan dikembalikan ke tabel menu. Proses dilakukan dalam transaction supaya pengembalian stok dan penghapusan pesanan konsisten.”

Dosen: “Kalau pengembalian stok gagal?”

Kamu: “Transaction di-rollback sehingga perubahan yang belum commit tidak dibiarkan setengah jalan.”

Simulasi C — Meja

Dosen: “Kenapa meja tidak langsung kosong setelah bayar?”

Kamu: “Karena pembayaran hanya menunjukkan status finansial. Pesanan masih bisa dalam proses pelayanan. Pada sistem ini meja baru dikosongkan setelah pesanan berstatus Selesai dan petugas menjalankan aksi Kosongkan Meja.”

Simulasi D — CSRF

Dosen: “Token CSRF disimpan di mana?”

Kamu: “Di session server. Form memasukkan token tersebut sebagai hidden input, kemudian endpoint POST membandingkan token form dengan token session menggunakan hash_equals().”

Simulasi E — Pagination

Dosen: “Kenapa halaman kedua offset-nya 5?”

Kamu: “Karena per halaman lima data. Rumusnya offset sama dengan page dikurangi satu dikali jumlah data per halaman. Jadi halaman 2: (2-1) × 5 = 5.”

Simulasi F — Database

Dosen: “Kenapa detail_pesanan tidak langsung disimpan di pesanan?”

Kamu: “Karena satu pesanan dapat berisi banyak item. Dengan tabel detail_pesanan, satu record pesanan menjadi header dan setiap item menjadi baris detail. Ini membuat struktur lebih normal dan memudahkan pengelolaan jumlah, harga, dan subtotal per item.”

15 · Cheat Sheet 5 Menit Sebelum UTS

PDO = interface PHP ↔ database.

prepare() = siapkan query dengan placeholder.

execute() = jalankan query + parameter.

fetch() = satu row.

fetchAll() = banyak row.

fetchColumn() = satu nilai.

ILIKE = pencarian PostgreSQL case-insensitive.

LIMIT = jumlah row yang diambil.

OFFSET = jumlah row yang dilewati.

password_hash() = membuat hash password.

password_verify() = memeriksa password terhadap hash.

session_regenerate_id() = mengganti session ID setelah login.

htmlspecialchars() = escape output HTML.

rollBack() = batalkan perubahan transaction.
